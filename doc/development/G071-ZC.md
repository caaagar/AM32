# G071 过零中断实验：拒绝旧边沿

基线：`main` 的 `a47e94c20c19e3b399b131d87499d2bc53b6ce3c`，版本 2.21。
用户现有电调报告为 2.20；本改动不是针对其二进制的补丁。

## 已确认的代码行为

`ADC1_COMP_IRQHandler()` 已有 `CNT > average_interval / 2` 门限。
当早期边沿的比较器电平仍符合预期，原代码不清除 EXTI pending。
这可能导致反复进入中断，并在时间门限到达后处理同一个旧边沿。
主机测试复现了 pending 保留及旧边沿延后处理；尚未证明它是实机失步根因。

## 本次实现

通过编译宏 `AM32_G071_STRICT_ZC_IRQ=1` 启用，默认值为 **0**。
可在编译器预处理定义中设置该宏；Keil 对目标的所有 C 文件使用同一设置。
GNU Make 可在 `g071makefile.mk` 的 `CFLAGS_G071` 中加入该定义。

启用后：

- 中断入口读取并清除本次看到的 COMP1/COMP2 边沿，不等待时间推进。
- 仅处理当前选中、已解屏蔽的比较器及预期极性。
- 保留原来的半周期门限及 `interruptRoutine()` 电平滤波。
- 提前到来的边沿不更新周期、不复位计时器、不安排换相。
- 再次开启比较器中断前清除两条比较器线路的旧 pending。
- 不修改 PWM、提前角、EEPROM、电流保护、引脚定义或启动轮询。

这只是第一阶段的边沿有效性保护，**不是完整自适应退磁算法**。
它没有增加电流估计、预测补偿换相或新的失步恢复动作。

## 限制与后续工作

真实过零若发生在门限前，也会被丢弃；若电平不再翻转，就可能漏检。
输入切换后、重新开中断前的真实边沿同样可能被清除。
默认保持关闭，待确认硬件 Target、时序波形及加速边界后再决定是否启用。
噪声持续翻转仍可能产生很多中断；这次只消除同一 pending 的反复处理。
ADC 共用中断入口的处理没有扩展。

36N40P 在机械 8000 RPM 时每个六步扇区为 62.5 us。
这不等于固定可用检测窗口；提前角、开关消隐、比较器延迟和退磁均会改变窗口。
不能把之前讨论的 10–15 us 直接写成通用退磁参数。

进一步开发需要：

1. 配置器中的准确固件 Target、现有参数及实际板卡电流采样配置。
2. 记录换相、浮空相电压、比较器输出、ISR 入口以及母线电压。
3. 从正常缓加速与突加速记录估计有效检测窗口，再设计有上限的动态屏蔽。
4. 电流瞬态限制须先确认采样带宽和标定；已有慢速母线电流不能直接视为相电流峰值。
5. 预测恢复必须有步数/时间上限和降功率退出条件，不能在持续无反馈时盲换相。

## 验证

运行 `python3 tests/test_g071_zc_irq.py`。
测试直接提取实际 G071 中断、解屏蔽函数和公共过零处理函数，以 W1C 寄存器模型编译运行。
覆盖宏关闭/开启、两条线路、两种极性、半周期门限前/等于/后、旧事件重放、
后续有效边沿、错误电平、屏蔽线路、非当前线路和其他 EXTI 标志保留。
启用编译警告及未定义行为检查。

该测试不是完整固件编译、周期精确仿真或电机试验。交付环境没有 ARM GCC，
且实际 Target 未确认，因此未生成可烧录固件。
台架应先记录默认模式，再以相同配置比较实验模式，观察漏检和中断占用。
带桨试验使用有防护固定台架及适当额定值的差分/隔离测量设备；验证前不用于实飞。
